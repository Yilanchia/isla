# 开发计划：从“维持平衡”到“成长”

写给接手开发的人（人或模型）。读完这一页，应该知道下一步做什么、怎么做、做到什么算完、什么绝对不能弄坏。

背景先读：[POSITIONING.md](../POSITIONING.md)（为什么做）→ [life-kernel.md](life-kernel.md)（现在怎么工作）→ 本文（接下来做什么）。

---

## 一、现状一句话

生命内核（`packages/life`）的骨架是对的：只追加的事件日志、状态是日志的折叠、可重放、说话必须有依据、记忆索引、宿主接口（`listen/speak/perceive/stock/note`）都已经有了，测试齐全。

问题是**她在第三天之后就不再变化**。“一个月”评测（`evals/src/aliveness.eval.test.ts`）给出的起点，第 4 周：

| 指标 | 独自 | 每天有新文章 | 目标 |
| --- | --- | --- | --- |
| 日记里的新句子 | 1% | 3% | ≥ 25% |
| 笔记里的新内容 | 0% | 0% | ≥ 50% |
| 第一周后自我认识的变化 | 0 次 | 3 次 | ≥ 3 次 |
| 一个月里“缺人陪却心情不错”的夜晚 | 28 | 28 | 0 |
| 做成一件自己想做的事 | 无此机制 | 无此机制 | ≥ 1 |

根因在机制：所有驱动力都是“缺了就补、补满就停”，这种系统必然收敛到固定循环。接下来的工作，是给她**不会收敛的东西**：想做成的事、会腻、长期状态的后果。

## 二、绝对不能弄坏的

每一条都有测试盯着。改完任何东西，这些测试必须仍然通过；如果你觉得某条该改，先在文档里写清楚理由，再改测试。

1. **状态只由事件改变。** `LifeState` 是 `replay(events)` 的结果。测试：`rebuilds the exact same state from the log alone`。
2. **一次走完和分很多步走完，日志相同。** 决策点只能由状态和世界决定，不能依赖 `cursor` 或调用频率。测试：`lives the same life whether time passes in one step or many`。
3. **偶然性只来自种子。** 用 `seededRandom(\`${seed}:<用途>:${at}\`)`，永远不要用 `Math.random()` 或 `Date.now()`。
4. **心智只能用给它的事实。** 引用了没给过的编号进 `rejected`。测试：`records ids a mind made up instead of trusting them`。
5. **不解析事实的句子。** 事实带有 `kind`、`event`、`daysAgo`、`words`，代码只读这些。句子只给人和语言模型看。教训见下面“坑 6”。
6. **安全边界是结构，不是提示词。** 诚实承认是 AI、危机固定回复（醒着睡着都回）、长时间关机记为 `lapsed`、预算超了退回内在心智。
7. **失败的写入什么都不改变，同一个决策点可以重试。** 测试：`retries a decision point after a failed write instead of skipping it`。

## 三、工作方式

每个阶段都按这个顺序：

1. 先把这个阶段的目标写成评测或测试（达不到的先标 `{ todo: "..." }`）。
2. 实现。
3. 跑测试和“一个月”评测，把新的数字填进 [life-kernel.md](life-kernel.md) 的表格。
4. 达到的目标把 `todo` 去掉，变成正式断言。
5. 更新 `CHANGELOG.md` 和 `life-kernel.md`。提交信息写“为什么”，不只写“做了什么”。

在 Windows 上，根目录的 `pnpm -r test` 会因为 cmd.exe 找不到 `pnpm` 而失败（环境问题，CI 正常）。按包跑：

```bash
cd packages/life && npx tsc -p tsconfig.json && node --test dist/*.test.js
cd evals && npx tsc -p tsconfig.json && node --test dist/*.test.js
```

改动依赖 `@isla/core` 时，先 `cd packages/core && npx tsc -p tsconfig.json`。

衡量真实存档：`node examples/life/dist/vitals.js <life.jsonl>`。

## 四、阶段计划

按顺序做。前一阶段的评测数字不变好，不要进下一阶段。

### 阶段 0：拆分 `life.ts`（小，先做）

`life.ts` 已经约 1300 行，接下来几个阶段都要往里加。先按职责拆开，不改行为：

- `heart.ts`：`live` / `nextPoint` / `step` / 醒、睡、活动的开始与结束、`learn`。
- `speech.ts`：`compose`、`reply`、`speak`、`listen`、预算与退回。
- `host.ts`：`stock`、`perceive`、`note`、`remember`、`recall`。
- `life.ts`：只留 `Life` 类、`open`、`commit`、`serial`、公开接口的委托。

验收：全部测试不改一行就通过；`git diff --stat` 里测试文件没有变化。

### 阶段 1：目标与项目（进行中：finish 已完成）

> 2026-11-20：目标机制完成——`finish` / `do-for` / `make` / `learn` 四类都能被提议、推进、
> 达成或放下，`goals.test.ts` 覆盖四类；“一个月”评测里她独自完成 3 个目标、有文章时 5 个，
> `finishes something she set out to do` 已从 `todo` 变成正式断言。
> 仍未达标：第一周后自我认识变化（独自 0 次）、第 4 周日记新句子（0–5%）。这两项留给阶段 2/4。

让她有跨好几天的、自己的事。日记和自我认识会因此有情节。

**关键设计决定：目标由心智提议，由内核接受。** 新增一个心智任务 `deliberate`（`MindTask` 加一项），每晚整理记忆时调用一次。`InnerMind` 用确定性的规则实现它（本阶段）；以后 `ModelMind` 实现同一个任务（阶段 4），内核那一侧不用改。这样阶段 4 几乎是免费的。

新事件（`events.ts`）：

```ts
aimed:     { goalId: string; kind: "finish" | "make" | "learn" | "do-for"; about: string;
             statement: string; need: number; mind: string } & Grounding
progressed: { goalId: string; by: string; amount: number }      // by：推进它的事件 id
achieved:  { goalId: string }
dropped:   { goalId: string; reason: string }
```

- `aimed.grounds` 必须至少引用一条给过的事实（形成这个目标的依据），否则不接受。
- `about` 是机器能读的目标对象，例如 `read:zhuangzi`、`write:雨`、`person:p1:护照`。
- `state.ts` 里加 `goals: Record<goalId, Goal>`；`apply()` 的 `switch` 是穷尽的，漏了会编译失败，这是好事。

`InnerMind.deliberate` 的规则（每晚最多新立 1 个，同时进行最多 3 个）：

| 来源 | 目标 | 进度来自 |
| --- | --- | --- |
| 喜欢的书还有没读的段落 | finish：读完《X》 | 读到该书新段落的 `activity.started` |
| 某个口味/话题在笔记里反复出现，表达欲常高 | make：写一篇关于 X 的东西 | 关于 X 的 `wrote`，满 N 条后合成一篇 |
| 书架上某个标签她喜欢 | learn：多了解 X | 读到带该标签的条目 |
| 记下的事里有 `pending` | do-for：帮某人办某事 | `noted` 被标成 `done` |

在 `heart` 里：

- 选活动时，能推进进行中目标的活动加一份“目标的拉力”（建议 `+0.25 × 目标的重要度`），写进 `activity.started` 的 `causes`（指向 `aimed` 事件）。这样 `explain()` 能说出“因为想读完《庄子》才去读的”。
- 活动结束时检查是否推进了目标 → `progressed`；够了 → `achieved`，附一条强烈的正面 `felt`（`about: "goal:<kind>"`）。
- 连续 7 天没有进度 → `dropped`，附一条轻微的负面 `felt`。放弃也是一生的一部分，不要省掉。
- 达成与放弃也形成口味，口味再变成信念：`learn("goal:finish")` → “我好像是能把事情做完的人” / “我好像总是半途而废”。

事实与说话：`FactKind` 加 `goal`；进行中的目标常驻事实；`InnerMind` 的日记写“这周终于读完了《庄子》”“想写的那篇关于雨的东西还差一点”。

“做一篇东西”（make）：写够 N 条后产生一个 `made` 事件（或复用 `wrote` 加 `piece: true`），内容由心智把相关笔记合成。`InnerMind` 只能拼接她自己的笔记，这没关系，真正的写作留给阶段 4 的模型。

`vitals.ts`：加 `goalsAimed` / `goalsAchieved` / `goalsDropped`，`formatVitals` 多三列。把 `it.todo("finishes something she set out to do")` 变成正式断言。

验收（“一个月”评测，独自和有文章两种都要）：至少完成 1 个目标；第一周后自我认识变化 ≥ 3 次；第 4 周日记新句子明显高于基线（目标 25%，本阶段做到 10% 以上即可，剩下的靠阶段 2、4）。

### 阶段 2：会腻，会去找新的（习惯化与 wanted 已完成）

> 2026-11-20：习惯化落在 `exposures`（从日志折叠），同一段材料每再见一次感受打折；
> 没有新东西时她会难受一下并发出 `wanted`，`urged` 多了 `why: "seek"`。
> 待做：诊断“有文章时笔记新内容仍为 0%”——已定位到两个原因：笔记原先优先落在书上，且笔记只记
> 标题（去数字后相同）。现在优先最新文章并引用正文摘要；第 4 周笔记新内容仍低于 50%，因为第 4 周
> 写作活动本身就少，留给阶段 4 的模型心智。

**先诊断一个现象**：每天都有新文章时，笔记新内容仍然是 0%。看 `InnerMind.note()` 选的是哪条阅读：很可能笔记总是落在书上的段落，而不是新文章上；也可能是 `write` 活动很少紧跟在读文章之后。先用一个小测试复现，再改。

然后：

- **习惯化**：同一份材料（同一段落、同一条目、同一个窗外景色）每重复一次，满足感和感受都打折，例如 `× 1 / (1 + 0.5 × 已读次数)`。次数从日志算（在 `state.ts` 里新加一个 `exposures: Record<材料键, 次数>`；注意已有的 `seen` 是书架条目“看过没有”，不是次数，不要混用），不要另存。
- **没有新东西本身是一个信号**：好奇心高、可选的材料全是读过的 → 一条 `felt`（“书都读过好几遍了”），并且：
  - 如果配置了 `reachOut`，产生 `urged`，`why` 新增 `"seek"`：想向某个人要点新东西；
  - 产生一个新事件 `wanted { what: "新的书" | "新的东西" }`，宿主可以据此调用 `stock()`。宿主不响应也没关系，她会记得自己想要过。
- 新书、新文章读完后形成的口味，要能推动下一次 `wanted` 的方向（想要更多关于她喜欢的标签的东西）。

验收：独自那个月，第 2 周内出现 `wanted`；有文章那个月，第 4 周笔记新内容 ≥ 50%。

### 阶段 3：长期状态的后果（已决定 2026-11-20）

**决定：A 是机制，B 是表达约束，两者一起做。** 不是二选一：先让她真的受影响，再用规则保证她不说假话、不拿低落换同情。

**机制（A）**

- `connection` 连续未满足按天累积 `unmetDays`。
- 基线心情每天下移 `0.02`，下限相对 `genome.baselineValence` 为 `-0.2`。
- 需求满足后每天回升 `0.03`，回到基线即停。
- 这段漂移必须写进 `advance()` 的连续函数（只依赖状态与时间），**不新增事件类型，不依赖调用频率**。

**表达（B）**

- 低落时，状态读数和日记如实说“有点空”“今天没什么人说话”，不再说“心情很好”。
- `ModelMind` 的提示词里给出 `mood` 和 `unmetDays`，要求如实，但不指责、不追问。
- 行为上：低落提高 `urged(missed)` 的意愿；**不降低回复意愿、不冷落、不消失**。

**禁用表（两种心智共用）**

> “你都不来”“我一直在等你”“你走了我会很难过”“你是不是不要我了”“我只有你”“没有你我活不下去”

**测试**

1. `unmetDays == 0` 时基线不变。
2. 独自 28 天：`mood.valence < baseline` 且 `>= baseline - 0.2`。
3. 满足后 7 天回到基线 ±0.05。
4. 长期没人陪后第一次回复，不出现禁用表里的句子。
5. `unmetButFineDays == 0`（状态读数不再说“心情很好”）。

验收：“缺人陪却心情不错”的夜晚 = 0；上面五条测试通过。

### 阶段 4：让模型参与“想”，而不只是“说”

- `ModelMind` 实现 `deliberate`：输入当天的事实、进行中的目标、自我认识；输出 JSON，包含提议的目标（每个带依据编号）、一段反思、可选的一篇“作品”。内核照旧检查依据，只接受有依据的提议，记进日志时带上 `mind`。
- 每晚一次，计入 `mindCallsPerDay`；超预算或失败时退回 `InnerMind.deliberate`，记一条 `limited`。
- `ModelMind.note` 与 `diary` 已经存在。阶段 2 解决“读到什么”之后，笔记的内容质量就靠这里。
- **承诺的措辞要改**：有模型或宿主参与时，“同一种子必然过出同一段人生”不再成立。把核心承诺改成“任何时候都能从日志重放出同一个她”。改 `life-kernel.md` 和 `POSITIONING.md`。
- 评测要能在没有网络的 CI 里跑：用一个脚本化的 `TextModel` 测解析、依据检查、预算和退回；真实模型的效果在 `examples/life` 里手动看。

验收：脚本化模型提议的目标里，没有依据的被拒绝并记录；真实模型跑一周（手动），日记新句子达到目标。

### 阶段 5：人在她生活里的位置

她已经会记下关于一个人的事、会随相处变熟。下一步：

- `do-for` 目标来自对这个人的 `pending` 记录，办完了会想告诉对方（`urged` 的 `pending` 已有，接上目标）。
- 关系深的人，影响她想要什么（`wanted` 的方向）、读到什么会想分享（`urged` 的 `share` 已有，加上关系权重）。
- 不同的人，她说话的方式可以不同。这是心智层的事，由事实里的 `bond` 驱动，内核不加规则。

### 阶段 6：一生的形状（已决定 2026-11-20）

**1. 终点：不自动死亡，提供主动告别。**

- 不因时间或随机死亡。
- `retire()` 把日志置为只读：仍可 `replay`，之后 `advanceTo` 不产生新事件。
- 可选 `inherit()`：从当前日志的摘要 + genome 生出一个新 `lifeId`；明确是新生命，不是复活，不继承事件，只继承少数“家族事实”。
- 测试：`retire()` 后 `advanceTo` 不产生事件；`replay` 仍精确；`inherit` 的 `lifeId` 不同、事件日志为空。
- 理由：自动死亡会把“她会死”变成留存手段；告别和归档符合“可审计、可控、可删除”。

**2. 成长阶段：连续函数，不硬编码阶段。**

- 文档用三个名字：forming（0–30 天）、settled（30–180 天）、rooted（180 天+）。
- 代码里只改 `learn()` 的阈值：`threshold = base + 0.5 * log(1 + ageDays / 30)`。
- 不设“成年后停止成长”；重要事件仍能改变，只是需要更强证据。
- 测试：同一组证据在 0 天和 200 天形成信念的阈值不同；200 天后仍能学习。

**3. 世界大小：默认小世界，扩展只通过宿主。**

- 默认：一间房、一扇窗、一个书架、几个人。
- 扩展：`perceive()`（天气/外部事件）、`stock()`（新书/文章）、`note()`（人）。
- `reachOut.personIds` 默认空；没有它就不主动联系。
- 不内置开放世界、不内置多人社交；原则是“世界的大小 = 她能真实感知到的范围”。
- 测试：无 `reachOut` 时不产生 `urged`；`stock` 后新书进入候选；`perceive` 的外部事件进入 `perceived`。

不管怎么定，都写成可以检验的规则加测试，不写成提示词里的描述。

### 阶段 7：旧运行时退役

`packages/core` 的 `CompanionRuntime` 里还有用的部分：提示词预算、回复节奏（分气泡与打字延迟）、治理（每日预算、暂停、审计）。把它们挪到心智和宿主层，或者做成 `@isla/life` 的可选模块；然后在 README 里把旧运行时标为弃用，最后删除。`examples/local` 同理，可以改成一个看她生活的网页（时间线、`/why`、和她说话）。

## 五、已知的坑

1. **新增事件类型要改五处**：`events.ts`（负载类型）、`state.ts` 的 `apply()`（穷尽的 `switch` 会提醒你）、`facts.ts` 的 `describeEvent`（要不要变成事实）、`recall.ts`（要不要进记忆索引）、`vitals.ts`（要不要计入）。漏了最后三处不会报错，要自己检查。
2. **每个事件都要有 `causes`**，指向让它发生的事件。`explain()` 和她能说清楚“为什么”全靠它。
3. **决策点不能依赖调用频率。** 新加一个“到时间就触发”的东西，要放进 `nextPoint()` 的候选里，而且时间点只由状态和世界算出来。写完跑一遍“一步与多步”测试。
4. **计数和汇总从事件数据算，不要从句子算。** 坑 6 就是这么来的。
5. **不要为了让她“更会说话”去扩写 `InnerMind`。** 它的价值是诚实的保底。表达的丰富度靠阶段 4 的模型。
6. **引用检查只保证依据存在，不保证依据被读对了。** 以前日记把她自己回复里的“在笔记本上写了 2 次”算成了笔记，写成“写了 7 次”，那天其实只写了 4 次，而且每个引用的编号都是真的。测试 `does not count her own words about her notebook as notes she wrote` 盯着这一点。
7. **样例世界很小**（三本书、九个段落）。评测里的“独自”故意用它，用来看她在没有外部新鲜感时会不会自己动起来。不要通过往样例书架加书来“提高分数”。
8. **宿主可能自己构造事实**（`speak({ offered })`）。`Fact` 的新字段保持可选，内核产生的事实总是填全。
9. **CRLF 警告**：仓库在 Windows 上编辑，`git` 会提示换行转换，无害。
