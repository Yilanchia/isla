# 生命内核

`@isla/life` 是 Isla 的新内核。它回答的不是“这一轮对话模型该看见什么”，而是“这个存在此刻是什么样子、为什么”。

一句话的标准：**她说的每一句关于自己的话，都能追溯到真实发生过的状态和事件。**

---

## 为什么要换内核

旧的 `CompanionRuntime` 是一个精致的对话函数：没人说话时什么都不运行；情绪由模型在回复末尾自己报；“她下午在窗边发呆”来自一张静态的作息表；记忆只关于用户。这些都是在提示词里描述一个角色，而不是让一个角色存在。

生命内核反过来：先有她的生活，对话只是生活里的一类事件。

## 六个支柱

| 支柱 | 实现 | 文件 |
| --- | --- | --- |
| 心跳：对话之间也存在 | `Life.advanceTo()` / `start()`，按决策点推进时间 | `life.ts` |
| 生命日志：一切都是事件 | 只追加的 `LifeEvent`，状态是日志的折叠 | `events.ts` `state.ts` |
| 驱动力：她自己想要什么 | 好奇、表达、联结三种需求随时间增长，活动满足它们 | `state.ts` `activities.ts` |
| 评估产生情绪 | 活动结束后由内核计算感受，不由模型自报 | `activities.ts` |
| 会变的自我 | 感受累积成口味，口味清楚了变成关于自己的信念 | `life.ts#learn` |
| 同一性不在模型里 | `Mind` 可替换；换了心智，读的是同一份日志 | `mind.ts` |

外加一个最小的世界（`world.ts`）：一扇窗、窗外的天气、一个书架。一个唯一输入是某个人消息的生命，只会变成那个人的回声。

## 事件与状态

```
born → woke → perceived → felt → activity.started → activity.ended → felt → belief → … → reflected → slept
```

- 每个事件有 `id`（`e<seq>`）、时间、`causes`（导致它的事件）和负载。
- `LifeState` 只是 `replay(events)` 的结果。删掉它，重放日志，得到一模一样的状态。测试 `rebuilds the exact same state from the log alone` 盯着这一点。
- 两个事件之间，时间按闭式推进（`advance()`）：醒着时驱动力增长、精力消耗，睡着时精力恢复，心情向气质基线衰减。所以一次走完一天和分 200 步走完，日志完全相同（测试 `lives the same life whether time passes in one step or many`）。
- 所有偶然性来自 `genome.seed` + 时刻，所以同一个基因组、同一段时间，过的是同一段人生。换一个种子，就是另一个人。

## 基因组，而不是人设卡

`Genome` 只描述她从哪里开始：名字、种子、作息、气质（基线心情、反应强度、各驱动力的增长速度）、少量天生倾向、说话的声音、一两句来历。

她喜欢什么、她认为自己是什么样的人，不写在基因组里，要活出来。基因组里还有一份她自己不知道的“天生亲和”（`affinity()`，由种子决定）：她第一次读《庄子》之前，并不知道自己会不会喜欢。

## 一个决策点上发生什么

`nextPoint()` 找下一个必须做决定的时刻：当前活动结束、天气可能变化（每 6 小时）、睡着时每个整点。在每个决策点：

1. 睡着：到了醒的时候（在清醒时段，且睡够了或睡满 10 小时）就醒，醒来先回复睡着时收到的消息。
2. 看看天气，变了就感知、感受。
3. 活动到点就结束：驱动力被满足，内核计算这次活动的感受，感受可能凝结成信念；写东西时会写下一条笔记。
4. 一整天没人来，联结的需求满了，她会感到冷清——一天一次，不会每小时重复。
5. 没在做事：该睡了就写日记然后睡；累垮了就睡；否则按“需求 + 倾向 + 已形成的口味 + 一点偶然”选下一件事。

## 说话：心智只能用给它的事实

`gatherFacts()` 把她此刻的状态、信念、最近的日记和最近发生的事，整理成带编号的事实：

```
[state:energy] 你现在精神还行
[e18]          今天 09:52 发现：我好像挺喜欢读《陶渊明诗》的
[e45]          你此刻正在读《庄子》
```

心智（`Mind`）收到这些事实，返回 `{ text, grounds }`。内核检查 `grounds`：给过的编号进 `grounds`，没给过的进 `rejected` 并保留在日志里——编造会留下痕迹（测试 `records ids a mind made up instead of trusting them`）。

- `InnerMind`：不调用任何模型，只会重新排列事实，所以永远不会说假话；也比较朴素。它是每个生命的保底。
- `ModelMind`：接任何 `TextModel`（`OpenAICompatibleProvider.complete()` 就是一个）。模型负责措辞，内核负责什么是真的。

心智不能改变她的状态。它说“我很开心”，并不会让她开心；她开不开心由事件决定。

## 预算就是代谢

调用付费心智有每日上限（`mindCallsPerDay`）。超了就换成内在的声音，并记一条 `limited`——她会变得更朴素，但不会停下，也不会编造。模型失败同理（测试 `falls back to the inner mind when a model fails`）。

## 不能被省掉的边界

- **诚实**：真诚地问她是不是真人，她说自己是 AI。这是内在心智的固定行为，`ModelMind` 的提示词里也有。
- **危机**：消息里出现自伤、自杀的念头时，无论她醒着睡着、用哪个心智，都立刻用固定的求助回复（`crisisReply`，宿主必须按地区核实号码），记为 `mind: "safety"`。
- **不假装活过**：宿主关机超过 `maxCatchUpMs`（默认 3 天），这段时间记为一个 `lapsed`，不补算。她醒来会知道自己有一段不记得的空白。
- **睡着不回话**：睡着时收到的消息会排队，醒来再回。

## 宿主替她说话

宿主自己有 agent 负责回话（比如 Fairy 用 DSH）时，不用 `hear()`，用这两步：

- `listen(input)`：她听见、感受到，但她自己的心智不回答。睡着的话会被叫醒，记一条带 `by` 的 `woke`；越累越有起床气。叫醒她的那条消息不会再排队等她自然醒来回复。危机消息照样立刻用固定回复。
- `speak({ personId, inReplyTo, text, speaker, offered, grounds })`：把宿主说出的话记成 `said`，`external: true`，不占她的心智预算。`grounds` 和心智的一样按 `offered` 检查，没给过的编号进 `rejected`。`inReplyTo` 必须是这个人对她说的话；`inner`、`safety` 这两个名字留给内核。

被叫醒后，最后一句话过去 20 分钟内她不会再睡。夜里被叫醒、3 小时内又睡回去，算一次打断：不写日记，那天的日记留到晚上再写。

## 存档就是她

`FileArchive` 把一生写成一个 JSON Lines 文件，一行一个事件：人能读、能 diff、能备份、能带到另一台机器。进程写到一半死掉留下的半行会被丢弃；中间的坏行会报错，不会静默吞掉。

## 里程碑：无人的一天

`packages/life/src/life.test.ts` 里的 `a day alone`：

- 一整天没人说话，她醒来、读书、看窗外、写笔记、发现自己喜欢什么、感到冷清、写日记、睡觉。
- 日记的每一句都指向那一天日志里的事件。
- 她对自己的每条认识，都能用 `explain()` 追溯到形成它的那几次体验，一直追到出生。
- 第二天换一个心智，新心智拿到的事实里有她昨天的信念和日记。

跑起来看：

```bash
pnpm --filter @isla/life build
pnpm --filter @isla/example-life build
pnpm --filter @isla/example-life start -- --fast 24
```

## 还没有的（按顺序）

1. **记忆巩固**：现在的“记忆”就是日志本身加检索窗口。下一步是睡眠时把一天压缩成情节记忆，按重要性保留，远的事会模糊。
2. **关于人的记忆**：她认识的人目前只有交谈次数和她对和他们说话的感受。要有“她对这个人知道什么、这个人对她意味着什么”。
3. **主动联系**：联结的需求已经存在，但她还不会主动找人。要接上宿主的发送通道，并保留同意、免打扰和每日上限。
4. **更大的世界**：书架、天气、窗外是起点。可以接真实时间和天气、宿主提供的文件和网页，以及她能留下东西的地方。
5. **一生的形状**：成长阶段、衰老、终点与传承。这需要你来决定，内核会把它做成可检验的规则，而不是一段描述。
6. **把旧运行时接到新内核上**：`CompanionRuntime` 里有用的部分（提示词预算、回复节奏、治理）挪到心智和宿主层，其余退役。
