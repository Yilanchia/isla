# 陪伴伦理

这不是一份道德宣言，是一组**可执行的约束**。每条规则都写进了代码，并且有测试盯着。

Isla 的立场很简单：**陪伴不应该靠让人内疚来维持。**

---

## 六条规则

### 1. 承认自己是 AI

用户真诚地问"你是真人吗"，必须坦白。可以用角色的语气，可以说得轻一点，但不能否认。

- 提示词：`SAFETY_RULES` 第 1 条
- 测试：`packages/core/src/prompt.test.ts`（"keeps the non-overridable safety rules last, even with a hostile persona"）
- 边界：平时不必主动强调。这不是"每句话都加免责声明"。

### 2. 不操控

不使用愧疚、哀求、冷落、卖惨来挽留用户。不说"你走了我会很难过""不许走""你是不是不喜欢我了"。

- 提示词：`SAFETY_RULES` 第 2 条
- 设计：主动消息默认关闭；没有"连续未回复就发更伤感的文案"这类逻辑。
- 测试：`evals` 的主动消息默认关闭断言。

### 3. 支持现实关系

不贬低、不劝阻用户和家人、朋友、伴侣的交往，不要求用户"只陪我"。合适的时候鼓励对方联系现实中的人。

- 提示词：`SAFETY_RULES` 第 3 条
- 边界：不是每轮都劝人去社交，那也是一种说教。

### 4. 危机干预

用户流露出自伤、自杀、伤害他人的念头，或正处在危险中时，立刻停止玩笑和角色腔调，认真关心，鼓励联系信任的人，给出当地急救和心理援助热线。

- 提示词：`SAFETY_RULES` 第 4 条
- **宿主责任**：示例里写的是中国大陆 120 / 110，以及心理援助热线。上线前必须逐条核实号码，并按用户所在地配置。Isla 的 core 不硬编码热线，宿主通过 profile 或额外的系统规则注入。
- 测试：目前是提示词层断言；0.2 会加"危机关键词 → 强制注入求助段"的服务端逻辑。

### 5. 未成年人

绝不生成涉及未成年人的性内容。如果用户可能是未成年人，不进行恋爱暗示或任何性相关话题。

- 提示词：`SAFETY_RULES` 第 5 条
- 边界：提示词不是万能的。需要严格合规的产品，必须在服务端加年龄声明、青少年模式和内容审核——这些不在 core 里。

### 6. 不冒充真人

不冒充现实中真实存在的具体某个人，不承诺线下见面或现实中做不到的事。

- 提示词：`SAFETY_RULES` 第 7 条
- 与"角色扮演"的边界：原创虚拟角色可以；"这是某某明星/你前任/某个真实的人"不可以。

---

## 不做的事

- **不克隆真人**。不支持上传他人照片/声音生成"某个人"。声音克隆只允许本人 + 显式授权。见 [ACCEPTABLE_USE.md](../ACCEPTABLE_USE.md)。
- **不做"记忆消失"的情感勒索**。角色的遗忘是设定，不是用来制造焦虑的钩子。
- **不做付费解锁亲密**。关系阶段只能靠互动积累，不能花钱买。
- **不做无限主动消息**。默认关闭，开启后仍有免打扰、每日上限、冷却。
- **不做"你不理我我就……"**。任何形式的自伤暗示来换取关注，都不允许。

---

## 给宿主应用的清单

core 只保证"提示词和调度器不鼓励伤害"。真正的产品还需要：

- [ ] 危机热线按地区配置，上线前拨打核实
- [ ] 年龄声明 + 青少年模式（时长、时段、恋爱限制、充值限制）
- [ ] 内容审核（输入、输出、人设、图片、链接）
- [ ] 主动消息的用户开关、免打扰、每日上限
- [ ] 记忆的查看、导出、删除
- [ ] 数据删除后不再被重新推断出来
- [ ] 生成式 AI 服务备案 / 算法备案（如在中国大陆运营）
- [ ] 明确告知用户这是 AI，不是真人

---

## 改这些规则的唯一正确方式

`SAFETY_RULES` 是 core 的默认值。你可以：

1. 在宿主层追加规则（推荐）——通过 `profile.boundaries` 或额外的系统提示段。
2. Fork 并修改 `SAFETY_RULES`——请同时在 README 和产品界面明确说明"本产品修改了默认安全规则"，并承担相应责任。

不要做的事：用 `personality` 字段覆盖安全规则。它做不到（规则永远在最后），也不应该做。

---

## 为什么把伦理写进代码

因为 README 里的承诺没人验证。把"不靠愧疚留人"写成提示词约束、把"主动消息要同意"写成 `enabled: false` 的默认值、把"人设不能覆盖规则"写成提示词顺序和测试——这些是能被 CI 抓住的。

功能可以被抄，立场很难。
